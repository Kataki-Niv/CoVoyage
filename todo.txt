Gemini issue:
Yes. I checked both, and the problem is very likely in Covoyage’s Gemini API request shape, not the API key.
Zenith works because it uses the official JS SDK:
- [zenith app/api/gemini-explanation/route.ts (line 1)](/C:/Users/KIIT0001/OneDrive/Desktop/project-zenith/zenith-app/app/api/gemini-explanation/route.ts:1) imports @google/generative-ai
- It reads process.env.GEMINI_API_KEY
- It calls getGenerativeModel({ model: "gemini-2.5-flash" })
- Then model.generateContent(prompt)
Covoyage is different:
- [covoyage backend/services/gemini_local_vibe.py (line 23)](/C:/covoyage/backend/services/gemini_local_vibe.py:23) defaults to gemini-3.8-flash
- [same file (line 25)](/C:/covoyage/backend/services/gemini_local_vibe.py:25) posts to:
  https://generativelanguage.googleapis.com/v1beta/interactions
- But Google’s current Interactions REST docs show:
  https://generativelanguage.googleapis.com/v1beta2/interactions
- Also, for structured output, Google says response_format should be a top-level array, but Covoyage sends it as a single object at [gemini_local_vibe.py (line 389)](/C:/covoyage/backend/services/gemini_local_vibe.py:389).
So the likely Covoyage issues are:
1. Wrong Interactions API version
   v1beta/interactions should be v1beta2/interactions.
2. Wrong response_format structure for itinerary generation
   Covoyage sends:
   request_body["response_format"] = {
       "type": "text",
       "mime_type": "application/json",
       "schema": response_schema,
   }
   It should be:
   request_body["response_format"] = [
       {
           "type": "text",
           "mime_type": "application/json",
           "schema": response_schema,
       }
   ]
3. Covoyage hides the failure
   In [backend/routers/assistant.py (line 248)](/C:/covoyage/backend/routers/assistant.py:248) and [backend/routers/assistant.py (line 320)](/C:/covoyage/backend/routers/assistant.py:320), Gemini errors are caught and replaced with deterministic fallback answers. So the UI does not crash; it just silently stops being Gemini-powered.
Your .env is not the obvious problem: Covoyage has GEMINI_API_KEY, same base env name Zenith uses.
Source checked: Google Gemini Interactions docs show v1beta2/interactions and response_format as an array in the REST examples: https://ai.google.dev/gemini-api/docs/migrate-to-interactions#structured-output
